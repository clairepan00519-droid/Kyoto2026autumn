# 京都・奈良・丹後 10 日慢旅網站

## v46 修正「同步後資料消失」與「家人看到的跟我不一樣」

**如果你已經在用舊版，請先做這一步：** 到 Supabase SQL Editor 重新貼上並執行一次新的 `SUPABASE_SETUP.sql`（可重複執行，不會刪資料），這會加上一個資料庫觸發器，讓 `updated_at` 一律由資料庫時間決定。

修正了兩個造成資料消失／版本不一致的問題：

1. **同步時間比較改用資料庫時間，不再用手機自己的時鐘。** 舊版由每台裝置自己蓋時間戳，只要有一支手機的系統時間不準（快、慢或時區設錯），比較新的資料就可能被誤判成比較舊而被覆蓋掉，或是這台裝置不再接受家人之後的更新，看起來像「卡住」在自己的版本。
2. **同步時改用合併而非整包覆蓋。** 舊版是「筆記」「自訂景點」「排序」等每一類資料一次整包互相蓋過去，如果你和家人在幾秒鐘內剛好都改了同一類裡的不同項目，其中一邊會被整包蓋掉、看起來資料消失了。新版推送前會先讀一次雲端最新內容，跟本機要送出的內容合併（聯集）後再送出，兩邊的變更都會保留。
3. **離線快取改成「先連網、連不到才用快取」。** 舊版手機／電腦會優先顯示上次快取的網站版本，即使你已經更新部署，家人裝置也常要重新整理兩次才會換到新版，這也是造成「看到的跟我不一樣」的常見原因。

⚠️ 這個合併機制目前是「聯集」而非真正的欄位級版本控制，所以理論上還是有一種情況會讓「明確的刪除」被合併回來（例如你剛好在別人離線很久之後、才刪除同一筆資料）。日常同時編輯（不同景點、不同筆記、不同照片）都不會再有資料消失的問題；如果要刪除某個項目，建議先確認家人裝置都已連網同步過一次再刪，最保險。

## Supabase 第一次安全設定

1. 登入 Supabase 專案，開啟 **SQL Editor → New query**。
2. 複製 `SUPABASE_SETUP.sql` 全部內容並按 **Run**。
3. 到 **Authentication → Users → Add user → Create new user**。
4. 輸入家人的 Email 與 Password；每位家人建立自己的帳號。
5. 建議勾選 **Auto Confirm User**，避免還需要收驗證信。
6. 重新整理網站，以剛建立的 Email／Password 登入。

`kyoto_sync` 只允許已登入帳號讀寫；匿名訪客無法直接修改行程。圖片網址可以直接顯示，但只有已登入家人能上傳或刪除。

## 離線觀看

- 網站必須部署在 HTTPS（GitHub Pages 可用），不能直接以 `file://` 開啟。
- 第一次請保持網路，開啟網站並等待頁首顯示「✓ 已可離線觀看」。
- 建議至少瀏覽一次各日期；外站封面會在第一次顯示後加入圖片快取。
- 離線時可看已下載行程、筆記與圖片；即時天氣、Windy 與新照片上傳需要網路。
- 曾在同一裝置成功登入後，離線時可按「離線查看已下載行程」。
